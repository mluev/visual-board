# Learning Kit — block contracts

> GENERATED by `npm run docs` from `src/kit/blocks/*/contract.ts`. Do not edit by hand.
> This file is everything you need to write a board. **Do not read `src/kit`.**

## Board file
One file per board: `boards/<slug>.board.tsx`. Start with `npm run new-board <slug>`, or copy `boards/go-slices.board.tsx`.

```ts
import { defineBoard } from '@kit';

export default defineBoard({
  slug: 'go-slices',            // must match the file name; URL is /b/go-slices
  subject: 'Go',                // groups boards on the course map
  lesson: 'Lesson 3',           // optional kicker
  title: 'Slices, from the inside',
  blurb: 'len, cap, append and shared backing arrays.', // optional, course map
  meta: ['~15 min', 'Beginner'],  // optional header pills
  lang: 'go',                   // optional default code language for highlighting
  blocks: [
    { type: 'Explainer', id: 'intro', props: { title: '…', body: '…' } },
    { type: 'Quiz', id: 'check', span: 'full', props: { questions: [/* … */] } },
  ],
});
```

- `id` is required, unique on the board, and stable: results are saved under it. Never rename an id once the learner has used the board.
- A block entry has exactly four keys: `type`, `id`, `span` (optional) and `props`. Everything else, including options like `kind` or `tone`, goes inside `props`.
- `span: 'full'` makes a block take the whole row; it is the only value. Without it, blocks flow into as many 460px+ columns as fit.
- Props are plain data. Some props accept a function (shown as `(p: number) => …`); write those inline or as helpers at the top of the file.
- Text props accept light formatting: blank line = new paragraph, `- ` bullets, `\`code\``, `**bold**`, `*italic*`, `[link](url)`.
- Run `npm run check` after writing a board. It type-checks and validates every prop and prints the exact path of any mistake, e.g. `blocks[3] (Quiz "check").props.questions.1.answer: answer must be an index into options`. In the browser, a block with bad props shows a red error card with the same messages.

## Recipe
1. **Understand**: an Explainer, plus one visual or chart block.
2. **Practice**: 2–3 practice blocks of different types. Prefer blocks where the learner produces an answer over ones where they only recognise it.
3. **Remember**: Flashcards (3–8 cards).
4. **Check**: Quiz (3–6 questions). Always write `explain` — it is what teaches.

The recipe is a shape, not a checklist: pick only blocks that fit the subject. **Never invent data.** Charts and Stats need real, checkable numbers (or a function that computes them). If the subject has no natural quantity, leave charts out.

Match the subject: code goes in `code` fields; languages, maths and everything else in plain text. Keep each block focused. Mix block types rather than repeating one. Don't invent new styles on a board; if a new block type is needed, add it to the kit.

## Results → review loop
- The app writes learner activity to `results/<slug>.json` (never edit it). Per block id: `{ type, status: "in_progress" | "submitted", progress, attempts: [{ at, score?, total?, items: [{ prompt, answer, expected?, correct?, needsReview? }], needsReview?, files?, meta? }] }`.
- `needsReview: true` means the block could not grade it (drawings, explanations, free text). Judge it yourself. `files` are saved next to the JSON (e.g. `results/go-slices/sketch-drawing.png`); open them.
- Give feedback by writing `reviews/<slug>.json` (the app never writes it). The open board updates live, no reload:

```json
{
  "board": { "feedback": "Overall comment shown under the board title." },
  "blocks": {
    "check": { "verdict": "partial", "feedback": "3 of 4 — see question 2.", "items": [{ "index": 1, "correct": false, "feedback": "Why…" }] }
  }
}
```
`verdict`: `"correct" | "partial" | "incorrect"` or short free text. `items[].index` is the index in `attempt.items` (0-based).

## Blocks
- **Core:** Explainer, Flashcards, Whiteboard
- **Check:** Quiz, Test
- **Charts:** BarChart
- **Practice (learner produces an answer):** ShortAnswer, Cloze, ExplainBack, WorkedExample, CodeExercise
- **Layout:** Callout, Stats

## Core

### Explainer
The teaching text of a board: a big title, short paragraphs, an optional code sample and numbered key points.
**Use when:** Start almost every board with one. Keep it short (2–3 paragraphs, 2–4 points) and put the depth in the blocks that follow.
```ts
props: {
  label?: string = "Explainer"  — Pill text, e.g. "Big idea", "Recap"
  title: string  — Headline, one line
  body?: string  — Paragraphs separated by a blank line. Supports `code`, **bold**, *italic*, [links](url), "- " bullets
  code?: string  — Code sample shown under the text
  lang?: string  — Code language for highlighting (defaults to the board lang)
  points?: string[]  — Numbered key points (01, 02 …)
}
```
**Variants shown in /kit:** textOnly (Prose only, custom label)
```ts
{ type: 'Explainer', id: '…', props: {
  title: "What a slice really is",
  body: "A slice is a small header that points into an array.\n\nSlicing never copies data.",
  code: "s := a[1:3]",
  points: ["len(s) is how many elements you can read.", "Always reassign: `s = append(s, x)`."],
} }
```

### Flashcards
Anki-style spaced-repetition deck. Flip a card, grade it Again / Hard / Good / Easy; "Again" sends it back into the session.
**Use when:** The "remember" step: vocabulary, definitions, formulas, API names. 3–8 cards per deck.
```ts
props: {
  title?: string  — Deck name next to the pill
  cards: Card[]
  shuffle?: boolean = false  — Shuffle the order each session
  initial?: "front" | "back" | "done" = "front"  — Starting state (for previews)
}

  Card = {
    front: string  — Term, question or prompt
    back: string  — Answer or definition
    hint?: string  — Small label above the front, e.g. "Go · built-in"
    example?: string  — Example sentence or usage shown on the back
  }
```
**Saves:** Resumes after reload. On deck complete: an attempt with items[{prompt: front, expected: back, answer: first grade, correct: first grade ≠ "again"}]; score = cards known the first time; meta.counts = grades given.
**Notes:** Keys: Space/Enter flips, 1–4 grades.
**Variants shown in /kit:** back (initial: "back" (revealed, grading)) · done (initial: "done" (summary))
```ts
{ type: 'Flashcards', id: '…', props: {
  title: "Slice vocabulary",
  cards: [
    {
      front: "len(s)",
      hint: "Go · slices",
      back: "Number of elements the slice holds.",
      example: "len([]int{1,2,3}) == 3",
    },
    { front: "cap(s)", back: "Elements available in the backing array from the slice’s start." },
  ],
} }
```

### Whiteboard
A freehand drawing canvas with pen, marker, eraser, 4 colours, 3 sizes, undo and clear.
**Use when:** When the learner should sketch: memory diagrams, a proof, a graph by hand, a map. Give a concrete prompt with a question they can answer by drawing.
```ts
props: {
  title?: string = "Scratchpad"  — Title next to the pill
  prompt?: string  — What to draw. Supports `code` and **bold**
  height?: number = 360  — Canvas height in px
  submit?: boolean = true  — Show "Submit for review" (only when there is a prompt)
}
```
**Saves:** progress = strokes (resumes after reload). "Submit for review" saves a PNG to results/<board>/<id>-drawing.png and an attempt with items[{prompt, answer: "<png path>", needsReview: true}]. Open the PNG to judge it.
**Variants shown in /kit:** blank (Plain scratchpad)
```ts
{ type: 'Whiteboard', id: '…', props: {
  title: "Sketch it",
  prompt: "Draw `a`, `s` and their shared backing array after `s = append(s, 9)`. What is `a[3]` now?",
  height: 380,
} }
```

## Check

### Quiz
Timed multiple choice, one question at a time. Feedback is held back until the end, then a score and a review of every answer with explanations.
**Use when:** The "check" step at the end of a board. 3–6 questions. Use Test instead when you want all questions on one page or multi-answer questions.
```ts
props: {
  title?: string = "Quiz"  — Shown on the intro screen
  description?: string  — Intro line. Default: "N questions · m:ss time limit…"
  questions: Question[]
  timeLimit?: number = 90  — Seconds for the whole quiz. 0 = untimed
  initial?: "intro" | "run" | "done" = "intro"  — Starting screen (for previews; boards leave it)
}

  Question = {
    q: string  — The question
    code?: string  — Code shown under the question
    options: string[]  — 2–8 choices
    answer: number  — Index of the correct option (0-based)
    explain?: string  — Why the answer is right. Shown in the review. Always write it
  }
```
**Saves:** One attempt per finish: score/total, items[{prompt, answer, expected, correct}], meta.secondsUsed. progress.best = best score.
**Notes:** Options are labelled A, B, C… Keys: 1–8 or A–H pick, Enter goes next.
**Variants shown in /kit:** running (initial: "run") · done (initial: "done" (results + review))
```ts
{ type: 'Quiz', id: '…', props: {
  title: "Slices check-in",
  timeLimit: 120,
  questions: [
    {
      q: "What is len(s) and cap(s)?",
      code: "a := [6]int{}\ns := a[2:4]",
      options: ["2 and 2", "2 and 4", "4 and 6"],
      answer: 1,
      explain: "len = 4 − 2. cap counts from index 2 to the end of a: 6 − 2.",
    },
  ],
} }
```

### Test
All questions on one page, untimed, submitted together. Supports single-answer and select-all-that-apply questions. Marks every option and shows explanations after submitting.
**Use when:** A calm check or a longer exam-style set, or when a question has several correct options. Use Quiz for a quick timed round.
```ts
props: {
  title?: string = "Quick check"
  questions: TestQuestion[]
  initial?: "blank" | "answered" | "submitted" = "blank"  — Starting state (for previews)
}

  TestQuestion = {
    q: string  — The question
    code?: string  — Code shown under the question
    options: string[]
    answer: number | number[]  — Correct option index, or an array of indexes for "select all that apply"
    explain?: string  — Why. Shown after submitting. Always write it
  }
```
**Saves:** One attempt per submit: score/total, items[{prompt, answer: picked option text(s), expected, correct}].
**Variants shown in /kit:** submitted (initial: "submitted" (marked))
```ts
{ type: 'Test', id: '…', props: {
  title: "Grammar check",
  questions: [
    {
      q: "Choose the correct sentence.",
      options: ["She don’t like coffee.", "She doesn’t like coffee."],
      answer: 1,
      explain: "Third person singular takes \"doesn’t\" + base verb.",
    },
    {
      q: "Which of these are prime?",
      options: ["21", "23", "27", "29"],
      answer: [1, 3],
      explain: "21 = 3·7 and 27 = 3³.",
    },
  ],
} }
```

## Charts

### BarChart
Bar chart of labelled values. Optionally live: a slider parameter feeds a function that returns the bars, and the note updates with it.
**Use when:** Comparing a handful (2–10) of quantities, or showing how they change as one parameter moves (complexity classes, frequencies, costs).
```ts
props: {
  title?: string  — Chart title
  data: Bar[] | (p: number) => Bar[]  — Bars, or a function of the slider value
  param?: Param  — Adds a slider; its value is passed to data() and note()
  note?: string | (p: number, data: Bar[]) => string  — Caption under the chart
  highlight?: number | string  — Bar to emphasise: index or label (-1 = last)
  unit?: string  — Suffix for values, e.g. "%", " ms"
  allowLog?: boolean = false  — Show a Linear | Log toggle
}

  Bar = { label: string; value: number }
  Param = {
    name: string  — Shown as "name = value"
    min: number
    max: number
    step?: number = 1
    value: number  — Starting value
    unit?: string  — Suffix after the value
  }
```
**Variants shown in /kit:** static (Static data with unit and highlight by label)
```ts
{ type: 'BarChart', id: '…', props: {
  title: "Why append is cheap on average",
  param: { name: "appends", min: 1, max: 64, value: 20 },
  data: n=>[{label:"copies",value:n*2},{label:"appends",value:n}],
  note: (n,d)=>`${n} appends cost ${d[0].value} copies.`,
} }
```

## Practice (learner produces an answer)

### ShortAnswer
Recall from memory: the learner types short answers. Case, punctuation, missing accents and small typos are accepted as "almost".
**Use when:** Facts, translations, conjugations, definitions, one-word or one-number answers. Prefer it over multiple choice when the learner should produce the answer.
```ts
props: {
  title?: string = "Recall from memory"
  questions: ShortQuestion[]
  initial?: "blank" | "submitted" = "blank"  — Starting state (for previews)
}

  ShortQuestion = {
    q: string  — The question
    answer: string | string[]  — Accepted answer(s). The first is shown as the correct one
    hint?: string  — Revealed on request
    explain?: string  — Shown after checking
  }
```
**Saves:** One attempt per check: items[{prompt, answer: typed text, expected, correct}]. Exact matches are correct; "almost" (typo/accents) is correct with note "almost"; anything else is marked needsReview so you can accept synonyms.
**Notes:** Enter checks the answers.
**Variants shown in /kit:** submitted (initial: "submitted" (right, almost, wrong))
```ts
{ type: 'ShortAnswer', id: '…', props: {
  title: "Irregular verbs",
  questions: [
    { q: "Past tense of \"go\"?", answer: "went", hint: "It doesn’t end in -ed.", explain: "go → went → gone." },
    {
      q: "Capital of Australia?",
      answer: ["Canberra"],
      explain: "A purpose-built compromise between Sydney and Melbourne.",
    },
  ],
} }
```

### Cloze
A passage with gaps the learner types into, with an optional word bank. Typos and missing accents count as "almost".
**Use when:** Vocabulary and grammar in context, key terms in a paragraph, filling in code keywords (with mono). 3–8 blanks.
```ts
props: {
  title?: string
  text: string  — Passage. Blanks are [answer] or [answer|alternative|…]. Newlines are kept
  bank?: boolean = true  — Show a word bank of the answers (sorted, so it gives no order away)
  mono?: boolean = false  — Monospace text, for code
  initial?: "blank" | "submitted" = "blank"  — Starting state (for previews)
}
```
**Saves:** One attempt per check: items[{prompt: the sentence with ___ for the blank, answer, expected, correct}]. Non-matching answers are marked needsReview.
**Notes:** Enter checks. Clicking a word-bank chip fills the next empty blank.
**Variants shown in /kit:** code (mono, no bank) · submitted (initial: "submitted")
```ts
{ type: 'Cloze', id: '…', props: {
  title: "How plants make food",
  text: "Photosynthesis happens in the [chloroplasts]. Plants take in water and [carbon dioxide|CO2] and release [oxygen].",
} }
```

### ExplainBack
Feynman-style: the learner explains an idea in their own words, then compares it with key points and ticks what they covered. "Send to tutor" saves it for you to judge.
**Use when:** Checking real understanding of a concept, cause or mechanism ("Explain why…"). Best after an Explainer. 3–5 key points.
```ts
props: {
  title?: string = "Teach it back"
  prompt: string  — The question, e.g. "Explain why the seasons happen."
  keyPoints: (string | KeyPoint)[]  — Plain strings or {point, keywords}
  initial?: "write" | "review" = "write"  — Starting state (for previews)
}

  KeyPoint = {
    point: string  — What a good explanation must say
    keywords?: string[]  — Words that auto-tick the point if they appear in the answer
  }
```
**Saves:** progress = draft text. "Send to tutor" adds an attempt: items[0] = {prompt, answer: their text, needsReview: true}, then one item per key point {prompt: "Key point: …", answer: "ticked" | "not ticked", needsReview: true}; score = self-ticked points. Judge the text against the points and reply in reviews/ (items[].index matches these items).
**Variants shown in /kit:** review (initial: "review" (self-check))
```ts
{ type: 'ExplainBack', id: '…', props: {
  prompt: "Explain why the seasons happen.",
  keyPoints: [
    { point: "Earth’s axis is tilted about 23.5°", keywords: ["tilt", "axis"] },
    "It is NOT caused by distance from the Sun",
  ],
} }
```

### WorkedExample
A solved problem, step by step with reasons, and three modes: Study (all shown), Faded (the second half hidden) and Solve (write every step).
**Use when:** Maths, physics, algorithms, grammar transformations: anything solved in steps. 3–6 steps. The learner studies it, then fades to solving alone.
```ts
props: {
  title?: string
  problem: string  — The problem statement
  steps: Step[]
  initial?: "study" | "faded" | "solve" = "study"  — Starting mode
}

  Step = {
    work: string  — The step itself, e.g. "3x = 21" (shown in monospace)
    why?: string  — The reason for the step. Also used as the hint
    accept?: string[]  — Other accepted ways to write this step
  }
```
**Saves:** One attempt per "Check steps": items[{prompt: "Step n of: <problem>", answer, expected: work, correct}] for the hidden steps; meta.mode. Wrong answers are marked needsReview (they may be an equivalent form).
**Notes:** Answers are compared ignoring spaces, with − and - (and ×, ·, *) treated as the same.
**Variants shown in /kit:** faded (initial: "faded")
```ts
{ type: 'WorkedExample', id: '…', props: {
  title: "Solving a linear equation",
  problem: "Solve for x:  3(x − 2) + 4 = 19",
  steps: [
    { work: "3x − 6 + 4 = 19", why: "Distribute the 3." },
    { work: "3x = 21", why: "Combine constants, add 2 to both sides.", accept: ["3x=21"] },
    { work: "x = 7", why: "Divide by 3." },
  ],
} }
```

### CodeExercise
A coding task with a real editor (syntax highlighting for any common language), hints revealed one at a time, and a solution. JavaScript runs against tests in the browser; other languages are write → send to tutor → compare with the solution.
**Use when:** Practising code: write a function, fix a bug, finish a snippet. Give JavaScript tests whenever the language is JS.
```ts
props: {
  title?: string
  language?: string = "javascript"  — javascript, typescript, python, go, rust, sql, java, c, cpp…
  task: string  — What to write. Supports `code` and **bold**
  starter?: string  — Starting code in the editor
  tests?: CodeTest[] = []  — Only run for JavaScript
  hints?: string[] = []  — Revealed one at a time
  solution?: string  — Hidden until the learner asks
}

  CodeTest = {
    call: string  — An expression, e.g. 'isPalindrome("racecar")'
    expect: unknown  — Expected return value (compared as JSON)
  }
```
**Saves:** progress = current code. JS: each "Run tests" adds an attempt with items[{prompt: call, answer: got, expected, correct}] and meta.code. Other languages: "Send to tutor" adds an attempt with items[{prompt: task, answer: code, expected: solution, needsReview: true}].
**Notes:** ⌘/Ctrl + Enter runs the tests.
**Variants shown in /kit:** go (language: "go" (send to tutor))
```ts
{ type: 'CodeExercise', id: '…', props: {
  title: "Palindrome check",
  task: "Write `isPalindrome(s)`, ignoring case and non-letters.",
  starter: "function isPalindrome(s) {\n  // your code\n}\n",
  tests: [{ call: "isPalindrome(\"racecar\")", expect: true }, { call: "isPalindrome(\"hello\")", expect: false }],
  hints: ["Lower-case it and drop anything that isn’t [a-z0-9]."],
  solution: "function isPalindrome(s) {\n  const t = s.toLowerCase().replace(/[^a-z0-9]/g, \"\");\n  return t === [...t].reverse().join(\"\");\n}",
} }
```

## Layout

### Callout
A short highlighted message: a tip, a warning, a key takeaway or a summary of what the learner just did.
**Use when:** One or two sentences that must not be missed (a common pitfall, a rule of thumb). Use sparingly, at most one or two per board; use Explainer for real teaching.
```ts
props: {
  kind?: "note" | "tip" | "warning" | "success" | "key" = "note"  — Sets colour and default label
  label?: string  — Pill text. Default by kind: Note, Tip, Watch out, Nice work, Key idea
  title?: string
  body: string  — Supports `code`, **bold**, bullets
}
```
**Variants shown in /kit:** tip (kind: "tip") · key (kind: "key" with bullets)
```ts
{ type: 'Callout', id: '…', props: {
  kind: "warning",
  title: "Nil maps panic on write",
  body: "Reading a nil map is fine; writing to it panics. Create maps with `make`.",
} }
```

### Stats
A row of big-number tiles (KPI style).
**Use when:** Key facts that are numbers: dates, sizes, complexities, percentages, results. 2–6 tiles.
```ts
props: {
  label?: string = "At a glance"  — Pill text
  title?: string
  items: Stat[]
  tone?: "teal" | "violet" | "orange" | "blue" | "gold" | "pink" | "ink" = "teal"
}

  Stat = {
    label: string
    value: string | number  — Big number or short text, e.g. 42, "O(n)", "1914"
    note?: string  — Small line under the value
    trend?: "up" | "down" | "flat"  — Adds ▲ ▼ ▬
  }
```
**Variants shown in /kit:** violet (tone: "violet")
```ts
{ type: 'Stats', id: '…', props: {
  title: "Slices in numbers",
  items: [
    { label: "Header size", value: "24 B", note: "ptr + len + cap" },
    { label: "Growth factor", value: "2×", note: "until 256 elements" },
  ],
} }
```
